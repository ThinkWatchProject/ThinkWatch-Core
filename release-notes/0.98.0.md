Core web search now connects directly to Google (Docs), DuckDuckGo and Bing without API keys or a browser runtime. Automatic search tries them in that order and switches sources when an engine fails or returns no usable results.

- Google (Docs) searches public web pages through a legacy Google Docs research endpoint. Requests are spaced at least six seconds apart, identical concurrent searches share cached results, and throttled or failing engines enter cooldown. Eligible public document contexts are used only to make the search request; no document is edited. This legacy endpoint depends on Google continuing to provide it and does not support regional preferences.
- Search adapters share bounded requests, browser-style HTTP headers, compression decoding, connection reuse, and isolated in-memory sessions where needed. HTTP and SOCKS proxies support search-engine DNS resolution while page reads retain public-address checks and pinned connections.
- Relevance checks reject unrelated results instead of presenting them as a successful search. Domain restrictions, URL normalization, page-text extraction and failure messages have been improved. Error responses retain the original cause and retry timing.
- Core advertises available search engines to Lite, so the connected gateway determines which sources the desktop can select. Existing configurations remain opt-in through Core execution under Routing → Auxiliary.

This release keeps a conversation that carries encrypted history on the upstream that encrypted it, so moving a route to another upstream no longer breaks a Codex conversation that is under way.

**Upgrade notes**

- The control-plane protocol version stays at 51, and the request store's schema is unchanged; nothing is cleared.
- No configuration key is added, renamed or removed.

**Conversations with encrypted history stay on their upstream.** OpenAI Responses hands clients encrypted state to send back each turn (`encrypted_content`: reasoning, compacted history, and the messages Codex sub-agents report to each other), and only the account that encrypted it can read it. Before, a conversation moved to another upstream, for example after its route was changed, failed every turn with `invalid_encrypted_content`.

- The gateway now remembers which upstream last answered each conversation, across configuration reloads, a cold cache and quiet upstreams. A conversation that carried encrypted content is remembered for 30 days; the record does not survive a restart of core.
- When more than reasoning is encrypted, the conversation goes back to that upstream only, whatever its rule now picks, with no failover. If that upstream was removed, the request is refused with `gw.route.sealed_upstream_gone`.
- When only reasoning is encrypted, that upstream is tried first and the others remain as fallbacks.
- The route decision records this as the new reason `sealed`.
- An upstream that refuses encrypted content it cannot read (with a 400, or with an error inside the stream) now fails the request with `gw.upstream.sealed_elsewhere`, which names the upstream and explains that the history was encrypted by another one.

Generation requests automatically adapt to upstream streaming and non-streaming support. Requests follow the client's mode first; an eligible HTTP 400, 422 or 501 API rejection can trigger one bounded trial of the opposite mode. A successful answer is converted back to the client's protocol and response framing, including tool calls and usage. Complete successful trials teach a working preference for 30 minutes, isolated by upstream account, model, API and request options.

Known request repairs take priority and share one automatic repair budget. Failed trials preserve the original error, partially delivered answers are never replayed, and configuration reloads clear learned preferences. Authentication, quota, rate-limit, overload and timeout errors do not trigger mode trials; a `Rate limit exceeded` message alone does not establish that a response mode is unsupported. Whole-to-stream conversion waits for the complete upstream answer. WebSocket requests and richer native output contracts that cannot be preserved by the response converters are excluded.

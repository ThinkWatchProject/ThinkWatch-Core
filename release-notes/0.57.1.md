This release answers requests other than POST in the gateway itself. Before, they were forwarded to an upstream and recorded as failed requests, so a client checking whether the gateway is a local model server sent those checks on to the upstreams.

**Upgrade notes**

- The control-plane protocol version is unchanged (31) and so is the request store's schema (23). ThinkWatch Lite 2026.9.26 includes 0.56.0 (protocol 30) and does not connect to 0.57.x: a server used with it stays on 0.56.0 until the app is updated to a release that includes 0.57.1.
- One message code is added: `gw.method.not_forwarded`.
- A GET, HEAD, OPTIONS, PUT or DELETE to a path the gateway does not serve itself now gets a 404 from the gateway instead of whatever the upstream answered to an empty POST.

**Requests other than POST.** Every upstream API the gateway forwards to takes POST, and the gateway always sent the upstream request as POST. Any other method that reached the catch-all route was sent on as an empty POST, recorded as a failed request and, with failover, tried on the next upstreams.
- Hermes Agent sends five such GETs when it starts (`/api/v1/models`, `/api/tags`, `/v1/props`, `/props`, `/version`) to tell whether a server is LM Studio, Ollama, llama.cpp or vLLM.
- An upstream that answered one of them with 200 made Hermes take the gateway for that kind of server.

These requests now get a 404 in the client's error format, after the key check, and are neither forwarded nor recorded. A request without a key still gets 401. `/v1/models`, `/v1beta/models`, `/api/hello`, `/healthz` and WebSocket upgrades are unchanged.

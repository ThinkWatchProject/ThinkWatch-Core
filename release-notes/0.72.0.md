This release fixes a crash that cut off streamed answers whose tool calls had a URL right after a non-ASCII character, records the cause when the gateway's code fails during a request, and makes redacted values come back exactly as they were in every kind of answer.

**Upgrade notes**

- The control-plane protocol version stays at 47; ThinkWatch Lite releases that include 0.71.0 connect to 0.72.0 and the other way round.
- The request store's schema and the configuration are unchanged; nothing is cleared.
- New message code: `gw.internal_panic`.
- For crates that embed the gateway: `tw_guard::redact::replace::restore_json` is removed (`restore` now escapes each value as deeply as it sits), and the ledger (`Ledger::table`, `replacements`, `placeholder_of`) holds decoded values. New: `replace::Form`, `json_escaped`, `apply_text`, `restore_text`, `stream::Restorer::text`, `Restorer::fresh_as`, `Restorer::rebook` and `sse::FrameRestorer::rebook`.

**Tool calls with a URL after non-ASCII text no longer break the stream.** Tool-call inspection looks for URLs in a tool call's arguments while they stream, and it is on in observe mode by default. Finding a URL's scheme cut a multibyte character in two when one stood right before `://`, as in `文档见：https://…`, and the gateway's code panicked: the client's stream ended with a transport error and the request was recorded as interrupted by an internal error. The scheme is now found byte by byte. Masking credentials in URLs on configuration lines had the same flaw and is fixed too. The fault dates from 0.58.0.

**Internal errors say where and why.** When the gateway's code panics during a request, the request's outcome now carries the panic's message and its place in the source (`gw.internal_panic`), and the panic is logged; before, it only said the request was interrupted by an error inside the gateway. Data that the standard library prints into some panic messages is left out.

**Redacted values come back exactly.** A value found in a request is now remembered as it reads, not as it was written in the request's JSON, and is put back in the form each place needs:
- A private key echoed in a streamed answer comes back with real line breaks instead of `\n`.
- A value inside a tool call's arguments, which are JSON text inside JSON, is escaped for every level it sits in, however deep, in streamed answers, whole answers, replays and WebSocket frames, so the arguments still parse.
- Codex's freeform tool input (such as `apply_patch`) is restored while it streams, including a placeholder cut across two pieces.
- Over WebSocket, a placeholder cut across two frames is restored, also when the client sends a new value while the answer streams; what is still held when the upstream disconnects goes through the same renaming, reply plugins and tool-call inspection as the rest of the answer.
- The same value seen in a request's JSON and in the decoded text a plugin reads now has one placeholder number, and a stored request shows the placeholder upstream received even when the client wrote the value with escapes such as `\u00e9` or `\/`.
Bodies with nothing to restore are passed on unchanged, byte for byte.

This release fixes two problems in 0.67.0's handling of Codex and Claude: a compaction summary could be stored without its secrets masked, and requests converted for older Claude models on Bedrock could be refused because of the cache breakpoints 0.67.0 adds.

**Upgrade notes**

- The control-plane protocol version (`CONTROL_API_VERSION`) stays at 43: a server can be upgraded from 0.67.0 on its own.
- The request store's schema is unchanged: upgrading from 0.67.0 keeps the request history.
- The configuration format is unchanged.
- Message codes are unchanged from 0.67.0.

**Compaction summaries are masked before they are stored.** The summary 0.67.0 gives Codex when a converted route compacts a session travels base64-encoded in the item's `encrypted_content`, which the masking of stored payloads could not see into. A key or other secret that appeared in the conversation could reach the stored request bodies inside it. Summaries are now decoded, masked with the same rules as the rest of the payload, and put back in place before anything is written to disk.

**Cache breakpoints for Claude on Bedrock follow AWS's list.** 0.67.0 added prompt-cache breakpoints to every converted request for a Claude model on Bedrock, including models Bedrock does not cache. They now go only to the Claude models AWS lists as supporting prompt caching: Claude 3.5 Sonnet v2, Claude 3.7 Sonnet, and Claude 4.5 and later. When an Anthropic-format or Bedrock upstream refuses a request because of breakpoints the gateway added, the request is sent once more without them, and that upstream and model get none from then on. Breakpoints a client marks itself are never removed.

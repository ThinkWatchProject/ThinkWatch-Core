Core now serves a native Codex model catalog at `GET /codex/models?client_version=<major.minor.patch>`. Changes to upstream models, aliases, enabled ranges, manual capabilities and gateway-key permissions appear on the next catalog request through the existing hot reload path. The standard OpenAI `/v1/models` response stays unchanged.

The catalog uses the same authentication, allowed source addresses and model permissions as inference. Version-matched upstream definitions retain their native instructions and tools when available. Ordinary upstreams use a conservative coding profile; aliases and routing candidates expose only capabilities they can support. Gateway credentials are never forwarded to upstream model endpoints.

Upstream metadata has a bounded cache and fetch deadline. Live model names and permissions are rebuilt on every request, including conditional requests. Catalog responses are limited to 1 MiB and support private caching with ETags. Codex can retain its own picker cache, so changes appear when the client refreshes its catalog or restarts; the gateway does not push updates into an already open picker.

ThinkWatch Lite 2026.11.7 configures remote discovery during Codex adoption. The initial connection updates client configuration once and requires a client restart. Subsequent model changes do not rewrite the client configuration. See [the setup and cache guide](https://github.com/ThinkWatchProject/ThinkWatch-Core/blob/main/docs/codex-model-catalog.md) for manual connections and profile behavior.

The control-plane protocol remains 58 and the request-store schema remains 28. Existing configuration, request history and usage history are preserved. No configuration or database migration is required.

Bundled SQLite is upgraded through rusqlite 0.41 to fix RUSTSEC-2026-0459 (CVE-2026-119375). The database format and request-store schema stay unchanged. Building the storage and Core binary crates now requires Rust 1.89 or later; shared client crates retain their existing declared minimum.

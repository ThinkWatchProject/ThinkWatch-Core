Core can now execute web search, read public pages, and find text within pages without requiring a search API key or an MCP server. Enable Core execution under **Routing → Auxiliary** in the matching ThinkWatch Lite release.

- Recognized Claude Code standalone WebSearch requests return search results directly, avoiding the auxiliary model call. Native Anthropic and OpenAI Responses web tools search or read pages in Core, then return the results to the normally routed main model. Main-model usage is still billed.
- Search can automatically choose available Bing or DuckDuckGo engines, with optional proxy, domain, cache, timeout, and concurrency settings. Language and region follow the Core host's system locale by default and can be overridden independently.
- HTTP JSON, native SSE, and Responses WebSocket requests use the same tool execution path. Hosted tool loops buffer their result before emitting SSE events; other requests retain their normal streaming behavior.
- Public-address checks, DNS-pinned proxy connections, redirect restrictions, and existing request screening protect page access. Reads support public text and HTML; client-side WebFetch, JavaScript rendering, and PDF extraction are outside this path.

Control API version 61 adds web-tool configuration, testing, and detected-locale information for the desktop UI. Core execution is opt-in; existing configurations continue to use upstream tools.

This release gives plugins a set of helpers for common edits and lets a hook change the object it receives without returning it. It also makes the dangerous-command check and placeholder restoring look at every choice of an answer, not only the first.

**Upgrade notes**

- The control-plane protocol version stays at 48; ThinkWatch Lite releases that include 0.74.0 connect to 0.75.0 and the other way round.
- The request store's schema and the configuration are unchanged; nothing is cleared.
- Plugins: a hook that changes the request (`onRequest`) or the tool call (`onToolCall`) it receives and returns nothing now applies those changes. They used to be dropped unless the hook returned the object.
- The two built-in plugins are rewritten with the helpers and behave as before. Copies whose code was not edited are updated.
- For crates that embed the gateway: `tw_plugin::Reply::on_text` and `on_text_end` take the text block's lane, and the sandbox guest ABI is `tw_abi_2`. The public API of `tw_guard` is unchanged.

**Plugin helpers.** Plugins have a global `tw`:
- `tw.appendSystem(req, text)` adds a line to the end of the system prompt unless it is already there.
- `tw.texts(req, fn)` passes each piece of editable text (system prompt, message text, tool results) to `fn` and replaces it with what `fn` returns.
- `tw.toolCalls(req, fn)` passes each earlier tool call in the conversation to `fn`; `tw.mapStrings(value, fn)` copies a value with every string mapped.
- `tw.replace(text, rules)` applies `[find, replacement]` rules in one left-to-right pass: strings match literally, regular expressions match globally, the rule listed first wins at a position, replaced text is not scanned again, and placeholders are never matched or split.
- `tw.streamReplace(rules)` returns `onReplyText` and `onReplyTextEnd` for stream mode. The streamed result equals `tw.replace` on the whole block; it holds back only what could still become a match (with regular expressions, the last 256 characters by default).
- `tw.lines` and `tw.pairs` read multi-line settings.

The helpers are plain JavaScript in the sandbox snapshot, with no new host imports; their results are checked like any other plugin result.

**Every choice of an answer is checked.** In a streamed Chat Completions answer the dangerous-command check read only the first element of `choices` in each frame, and Gemini answers only their first candidate. An upstream could get a tool call past the check by placing it in a second choice, or by spreading its arguments across two choices. Every choice and candidate is now checked, and streamed Chat arguments are assembled both by choice index and by position in the frame, matching both ways clients read them. Placeholders in a streamed answer with several choices are restored per choice.

**Reply plugins**
- A stream-mode plugin that cut a placeholder in two left the placeholder text in the answer instead of the original value. The unfinished half is now held and restored together with the next piece.
- A stream-mode plugin that failed and was skipped could lose the text it was holding (when it failed in `onReplyTextEnd`) or release it out of order (when it failed in another text block). Both are fixed.
- Answers with several choices (`n` greater than 1, `candidateCount` greater than 1) mixed the choices' text and tool calls in plugins, and only the first choice of a whole answer went through them. Each choice is now kept apart, and every choice goes through the plugins.
- A stream-mode plugin that holds text back without changing it is no longer recorded as having changed the text; the run record compares each block as a whole.

**Dependencies:** wasmtime 49.0.3 and rustls 0.23.46 (RustSec advisories).
